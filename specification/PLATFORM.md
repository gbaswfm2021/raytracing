# Platform profile

Author and maintain `raytracing.schema.json` using FullMeta's Schema Editor: open the existing raytracing application with **Edit app**, use the editor's structured controls for the model structure and UI declarations, validate, and save. Follow the [Schema Editor guide](../../../platform/schema-editor/docs/schema-document-editing.md). Application runtime code and the example project are separate from the schema and may be implemented in their normal source files.

Register an application runtime package in `catalog.json` using `runtimePackage: true`, a schema loader and a package. The interpreting schema must also declare `x-fullmeta-runtime.schema` as `fullmeta-model-runtime/1` so FullMeta loads that package. See the [application development guide](../../../platform/docs/application-development.md) and [application platform contract](../../../platform/docs/application-platform-contract.md). The package connects Study, persisted results and the **Clear Results** action to shared Model Editor save and Graphics Console services. The schema declares `raytracingResult` as an optional project field; author that declaration through Schema Editor's structured controls, then validate and save it. If a required schema declaration cannot be authored or maintained through Schema Editor, record the exact limitation as a platform blocker rather than silently editing the schema JSON directly.

The shared [scene view](../../../platform/ui/widgets/scene-view/README.md) accepts 3D points, polylines and triangles; use it for the geometry and rays. The host manages interaction. Verify rotation and zoom through the Model Editor; if the shared integration cannot provide them for this scene, document the missing capability rather than silently substituting a 2D view. Gerchberg-Saxton is a reference for the Study workflow, not for ray optics.
